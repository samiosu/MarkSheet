# UIレビュー・検証記録

2026-09-07。`emil-design-eng` を適用し、白と薄いグレーを基調にしたシート型UIを実装・レビューしました。

## レビュー結果

| Before | After | Why |
| --- | --- | --- |
| 初期の補助文字は背景とのコントラストが2.03〜4.45:1となる箇所があった | 基本の補助文字を `#606b7f` に変更し、関連する配色・小さな文字も調整。主要画面のaxe検査で指摘0件 | シートの明るさを保ちながら、説明・未回答・保存状態を読み取れるようにする |
| 採点対象外の獲得点欄は「—」だけを表示していた | 「— / 配点」と表示。集計には含めない | 対象外の問題でも設定された配点を確認できるようにする |
| 保存データの削除に失敗すると、画面の作業だけが先に消える可能性があった | 保存キーの削除が成功してから画面をリセット。拒否時はエラー表示とともに現在の作業・出力機能を保持 | 保存状態と画面が食い違ってデータを見失うことを防ぐ |
| 連続入力とキーボード操作は未検証だった | 標準ラジオ入力、ラベル、解除ボタン、タブの矢印操作をブラウザーで確認。マーク選択・解除にはアニメーションなし | 繰り返し操作に待ち時間を生じさせない |
| 狭い画面と200問のレイアウトは未検証だった | 375px幅で選択肢を折り返し、長い選択肢と問題番号の対応を維持。200問×10選択肢で先頭・中間・末尾の操作と出力を確認 | スクロールと入力を妨げず、全文を読めるようにする |
| モーション設定・タッチ環境の挙動は未検証だった | hover表現はマウス環境に限定。タッチ環境の操作対象は44px以上の高さを確保し、reduced motionでは移動・拡縮を抑止 | タッチで状態が残る問題や、不必要な動きを避ける |
| ファイルに種別・ID・構成・配点を含め、読込先を自動判定していた | CSV／JSONをlabelとanswerだけに統一。解答／正答はタブまたは初期画面の読込先で指定する | 依頼された2項目の形式で外部ファイルを作成・再利用できるようにする |
| ファイルから構成を復元する前提で確認していた | 新規読込時は選択肢テンプレートとシート名を確認。既存シートへは番号で照合し、配点と反対側を保持する | ファイルにない情報を確認し、意図しない置換を防ぐ |
| 読込プレビューは集計情報だけだった | 先頭5問の番号・選択値を表で確認でき、番号不一致などのエラー中は確定できない | 読み込む内容と置換先を確定前に確認できるようにする |
| 任意の選択肢を使うには、テンプレートを先に作成する必要があった | 新規作成・新規読込・シート設定に「自由に入力」を追加。既存の追加・削除・上下移動ボタンで個数と順序を変更できる | 2択・3択・6択などを、その場で設定して学習を始められるようにする |

## 実行した検証

| 検証 | 結果 |
| --- | --- |
| TypeScript型検査 | 成功 |
| ESLint | 成功 |
| Vitest | 89件成功 |
| Vite本番ビルド | 成功。`/MarkSheet/` 配下でアセットを読込 |
| Playwright | 30シナリオ × 3環境、計90件成功 |
| axe | 自由入力の6択設定・初期画面・ファイル読込ダイアログ・解答・正答・設定・テンプレート・結果の各画面で対象ルールの指摘なし |
| 視覚確認 | スマートフォン幅の自由入力6択設定を追加確認。以前の変更では読込ダイアログ・初期画面・解答シート・200問シートも確認済み |

ブラウザー環境はChromium（PC 1440×1000）、Chromium（スマートフォン幅375×812）、WebKit（スマートフォン幅375×812）です。ブラウザーテストはViteの本番ビルドをHTTP配信して実行しています。

確認したシナリオには、手入力／CSV／JSONの全9通りの採点、JSON・CSVのダウンロードと再読込、正答先行、空の解答配布、異なる行順、不一致・破損ファイルの拒否、確認のキャンセル、構成変更、テンプレート操作、未採点への復帰、保存失敗・保存破損・削除拒否を含みます。200問の操作中に外部オリジンへの要求が発生しないことも確認しました。

2項目形式への変更では、メタデータが出力に含まれないこと、外部で作った2列CSV、番号の先頭ゼロ、問題の欠落・重複・余分な項目の拒否、正答読込時の配点保持、新規シートへの切替、従来の内部保存データからの復元を確認しました。サンプルの2／6点を再現する配点は画面で設定します。新規読込時の各1点では1／3点になります。

任意の選択肢への対応では、自由入力の2択・3択・6択で作成・入力・採点・出力・再読み込みを確認しました。ファイル読込時の6択指定、空欄・重複の拒否、上下移動、選択肢の削除、共通設定の全問・追加問題への適用も、3つのブラウザー環境で確認しました。

## 確認範囲

- 今回の形式変更はローカルの本番プレビューで検証しました。GitHub Pagesへの変更の反映・公開確認は行っていません。
- 実機のスマートフォン、OSのスクリーンリーダーによる読み上げ、Firefoxでの動作は未検証です。WebKitのモバイルエミュレーションは実機Safariでの確認を代替しません。
- axeの結果は対象の自動検査ルールについての結果であり、アクセシビリティ全体の認証ではありません。
- Windowsの制限付き実行環境ではテスト用サーバーの終了処理が制限されたため、最終のブラウザーテストは起動・終了を同じ許可された権限で実行しました。

再現コマンドはREADMEの「テスト」を参照してください。スクリーンショット・トレース・HTMLレポートは実行時に生成され、Git管理の対象外です。
